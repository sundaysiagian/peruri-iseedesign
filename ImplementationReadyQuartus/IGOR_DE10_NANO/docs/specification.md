# IGOR implementation specification
Mode A: FPGA-only demonstrator; no HPS bridge, no physical motor. Default 512 candidates, 20 poses, four tiles, 128x128 8-bit costmap. Target clock 50 MHz. FPGA 5CSEBA6U23I7. Header identity is supplied by the user, not inferred team membership.
The implemented subset uses a point robot on a host-inflated costmap, local origin (64,64), goal (96,64), forward speeds 0..15, angular codes -16..15. Dynamic-window and output delta limits refer to the last accepted command; measured vehicle velocity, braking-distance admissibility, full footprint checking and Nav2 integration are outside this demo. This limitation prevents industrial safety claims.
Full snapshots must arrive in strictly ascending addresses 0..16383, one byte per write clock. Sequence is strictly increasing unsigned 32-bit, no wrap. Recovery at sequence exhaustion requires a new reset/session. Begin/write/commit are mutually exclusive. Commit only when planner is idle. Inactive-bank updates while running are allowed; failed updates invalidate permission, but never modify active-bank data. Integrity/authentication and malicious-but-well-formed map detection are not implemented.
Configuration is a single atomic word, version 1, locked until reset. Security faults latch until reset. Freshness is elapsed fabric clocks from commit, max 1,000,000 clocks (20 ms); sender acquisition age is not known. Host must acquire a fresh map before upload. Watchdog permits elapsed <1,000,000 clocks. Command lease expires at that boundary. Freshness is checked continuously.
Targets: control 50 Hz, end-to-end p99 <=5 ms; these are not results. Full map logical size is 32 KiB; four read replicas consume 128 KiB physical data. Each tile has its own synchronous read port; updates broadcast. No fabric-generated clocks.
